The four questions

  1. Where am I? Use pwd.
  2. What is here? Use ls or ls -lah.
  3. What exact path will the command read or change? Resolve relative paths from the current working directory.
  4. How will I check the result? Inspect output, an exit status, or Git state.

    Why the working directory decided everything

    Python found and ran the script both times, because you gave a correct path to the script itself. The failure happened inside the script, at open("data/sample.csv"). A relative path starts from your current working directory, not from the folder that contains the script.

    from ~/project data/sample.csv → ~/project/data/sample.csv exists
    from ~/project/scripts data/sample.csv → ~/project/scripts/data/sample.csv missing

    That is why the habit is: run project scripts from the repository root. When a path error appears, check pwd first and read the missing path in the error before touching the code. Try cd .. and rerun it to see the fix.

  8. Tidy up, then check with Git. Move the summary into results/. From the root that is mv summary.txt results/; from elsewhere, build the path with ../. Then run git status and answer below. Question 4: how will I check the result?

Before Friday’s quiz

  • pwd, ls, and cd are your compass: where am I, what is here, move.
  • A relative path starts from the working directory; an absolute path starts from the file-system root.
  • .. is the parent directory and ~ is your home directory. cd - returns to the previous one.
  • Tab completion prevents typos. Use it whenever possible.
  • Run project scripts from the repository root, so the relative paths inside them resolve correctly.
  • git status is the safe first move in any confusing situation: it reads state and changes nothing.
