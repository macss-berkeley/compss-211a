4·Keys leak through URLs

OpenAlex accepts an optional key as a query parameter, which means response.url, logs, error messages, and screenshots can leak it.

That key is now part of the URL. Anything that prints the URL (a traceback, a saved notebook output, a screenshot for your AI Usage Journal) exposes it. Keep keys in environment variables or Colab Secrets, never in code or displayed URLs.

✓Before Friday’s quiz

  • A request is endpoint + method + parameters + headers; a response is status + headers + body. Read them in that order.
  • 200 accepted · 400 your request is malformed · 401 credentials missing/invalid · 404 wrong path · 429 slow down · 5xx their problem.
  • Cursor pagination: start at cursor=*, follow meta.next_cursor, and write the stop rule before collecting.
  • Handle 429 and transient 5xx with a small, bounded number of retries and a finite timeout, never an infinite loop. The cached fixture is the fallback in class.
  • Keys stay out of notebooks, URLs, logs, and screenshots. Redact before saving provenance.
  • A 200 means the server accepted the request. Keep claims inside the filters.
