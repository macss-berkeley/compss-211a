Four places, one change

Git records snapshots of a project's files. Each snapshot, or commit, has a message and a place in the project's history. Git is the version-control software; GitHub hosts the remote repository. The two copies do not synchronize automatically.

The part that trips people up is where a change lives after each click. Below, one file makes the full trip: your disk → the staging area → your local history → GitHub. Watch it move.

Before Friday's quiz

  • save ≠ commit

    Saving a file only changes your files on disk; a commit records selected changes, with a message, in your local history.

  • commit ≠ push

    A commit records local history; a push transfers commits to the remote. GitHub sees nothing until you push.

  • pull is not optional

    Pull brings the remote's new commits to your local repository; a teammate's pushed work never appears on your machine by itself.

  • Pages = remote

    GitHub Pages rebuilds the site from the pushed repository (the remote), not from the files on your laptop.
